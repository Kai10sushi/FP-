# 音声文字起こし

このプロジェクトには、録音したナレーションを文字起こしし、映像の切り替え位置を確認するためのローカル処理を追加しています。

## 使い方

プロジェクトのフォルダーで、PowerShellから実行します。

    npm run transcribe:m4a -- "C:\\path\\to\\recording.m4a"

出力先は transcripts/ です。

- .txt：全文
- .srt：発話区間つき字幕
- .json：全文・発話区間・モデル名

初回だけ、Xenova/whisper-small のモデルファイルをHugging Faceから取得します。モデルは .cache/transcription/ に保存され、次回から再利用されます。初回取得後は次のようにオフライン実行できます。

    npm run transcribe:m4a -- "C:\\path\\to\\recording.m4a" -Offline

PowerShellのスイッチをnpm経由で渡しにくい場合は、直接実行します。

    powershell -ExecutionPolicy Bypass -File scripts/transcribe-audio.ps1 "C:\\path\\to\\recording.m4a" -Offline

## 安全性とデータの扱い

- 録音ファイルは外部の文字起こしサービスへ送信しません。
- m4aから一時WAVを作り、処理後に削除します。
- 音声認識はプロジェクト内のNode依存パッケージと、キャッシュしたモデルで実行します。
- モデル取得時だけ、モデルファイルをHugging Faceからダウンロードします。音声データのアップロードではありません。
- 音声認識の結果は誤ることがあります。制度名・金額・条件は必ず台本と照合してください。
- npm install はインストールスクリプトを実行しない設定で導入し、npm audit は既知の脆弱性0件を確認済みです。

## 他の手段との比較

| 手段 | 音声の扱い | 長所 | 注意点 |
|---|---|---|---|
| 今回のローカル処理 | PC内 | 無料で繰り返せる、時刻を取得できる | 初回のモデル取得、PC性能に左右される |
| OpenAIの音声文字起こしAPI | 外部送信 | ローカルのモデル実行環境を用意せず利用できる | APIキー・料金・音声を外部へ送る判断が必要。今回との精度比較は未実施 |
| YouTubeの自動字幕 | YouTubeへアップロード | 手軽 | 公開設定、外部サービス、字幕の細かな制御 |
| Windows標準の音声入力 | 利用機能ごとに確認が必要 | 追加導入が少ない | 録音ファイル処理への対応やデータ送信条件は未確認 |

今回の「自分の声を録音し、Remotionの画面に合わせる」用途では、現在のローカル処理を標準手段にします。
