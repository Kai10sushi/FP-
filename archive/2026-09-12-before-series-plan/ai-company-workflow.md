# AI会社型ワークフロー

## 1本の流れ

```text
X・コメントの信号
  → 企画ブリーフ
  → 公式情報パケット／主張台帳
  → 事実レビュー
  → 生活場面への翻訳
  → 台本初稿
  → 品質・コンプライアンスレビュー
  → 人間オーナー承認
  → 人間が公開
  → 計測・実験ログ
```

## 引き継ぎの必須項目

すべての担当は、次担当へ以下を残す。

- 案件IDと現在の状態
- 目的と対象者
- 完了したこと
- 参照した公式URLと確認日
- 未解決点
- 禁止事項・停止条件
- 次担当への具体的な依頼
- 人間の判断が必要な点

## 記憶の階層

1. **会社憲章**：使命、対象者、禁止事項、公開基準。人間のみ変更
2. **制度の正本**：`source-log.md` と公式情報パケット。更新日・施行日・確認日つき
3. **承認済み知識**：制度の一般説明、誤解されやすい点、再確認期限
4. **作業メモ**：調査中の候補、レビューで出た質問
5. **アーカイブ**：古い数字、却下案、訂正履歴、失敗

XやAIの出力は、直接「制度の正本」へ昇格させない。

## 定期実行の境界

| 実行 | 許可する作業 | 禁止する作業 |
|---|---|---|
| 週次 | X信号・コメント・制度更新の要約、レビュー待ち一覧 | 自動投稿、トレンド投稿、返信・DM |
| 月次 | KPI・制作時間・失敗の棚卸し | 使命・ポリシー・権限の自己変更 |
| 改正時 | 影響しそうな台本の候補抽出 | 自動訂正・自動削除・外部連絡 |

## 停止条件

- 公式情報源が確認できない
- 数字、期限、対象、例外が曖昧
- 台本と主張台帳が一致しない
- 個別の給付・加入・投資・税務判断になっている
- 本業・顧客・個人の秘密情報が含まれる
- Xの規約・勤務先ルール・法的境界が不明
- AI同士のレビューが同じ根拠だけを反復している

停止した案件は削除せず、理由と再開条件を記録する。
